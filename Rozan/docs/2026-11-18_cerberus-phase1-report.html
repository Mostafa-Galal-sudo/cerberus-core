1. الملخص التنفيذي

اكتمل بناء المرحلة الأولى (Software Core) من منصة CERBERUS بالكامل: حلقة مغلقة من خمس طبقات تبدأ بتوليد هجمات محاكاة عبر وكيل LLM، وتنتهي بعزل آلي للأجهزة الخبيثة بعد تأكيد وكيل دفاعي — مع تفسير لكل إنذار عبر SHAP/LIME، وبدون أي اعتماد على راوتر معين أو هاردوير. كل الكود مرفوع على GitHub داخل فولدر Rozan/ في مستودع Mostafa-Galal-sudo/cerberus-core.

2. ما تم تنفيذه بالتفصيل

2.1 التأسيس والبنية (Scaffolding)

  • بيئة افتراضية Python 3.12 (64-bit) عبر py -3.12 -m venv .venv — ملاحظة حرجة: بايثون النظام 3.14 (32-bit) لا يملك wheels جاهزة لمكتبات scipy/scikit-learn/shap.
  • هيكل الحزم: agents/ · detection/ · gateway/ · backend/ · frontend/ · tests/ · scripts/ · docs/ · firmware/
  • ملف requirements.txt + قالب أسرار .env.example + ملف AGENTS.md توثيق فيه الأوامر المُتحقق منها والمزالق.
⚠️ مزالق مُوثّقة: الخادم يُشغَّل كوحدة python -m backend.app (التشغيل كملف مباشر يكسر import config)؛ اختيار قاعدة البيانات عبر متغير البيئة DB_PATH (الافتراضي cerberus.db، وdemo.db للبيانات التجريبية المُسرعة).

2.2 خط بيانات CICIoT2023 والمولّد المحاكى

  • detection/schema.py: مخطط ميزات كانوني — 48 عمود ميزة + label + attack_class + is_attack، مع مطابقة أسماء غير حساسة لحالة الأحرف/الفواصل من أي CSV.
  • detection/data.py: محمّل CSV بالتجزئة (chunked) لملفات CICIoT2023 الضخمة.
  • detection/simulator.py: مولّد traffic محاكى بنفس المخطط — 6 سيناريوهات ببادئة Sim- وخريطة أصناف هجوم خاصة بها:
السيناريوLabelالصنفالتوقيع
mqtt_benignSim-MQTT_BenignBenignTrafficتليمتري MQTT طبيعي (TCP, Rate≈15.7)
mqtt_floodSim-MQTT_FloodDoSRate > 100k, SYN/RST-heavy, تدفقات قصيرة
mqtt_injectionSim-MQTT_InjectionSpoofingRate طبيعي لكن إحصائيات حجم شاذة (Header 90–400)
mqtt_spoofSim-MQTT_DeviceSpoofSpoofingنفس عائلة التزييف
wifi_deauthSim-WiFi_DeauthDoSتوقيع الفيضان على طبقة 802.11
wifi_rogue_apSim-WiFi_RogueAPSpoofingتوقيع التزييف

2.3 محرك الكشف الهجين (Hybrid IDS)

  • detection/rules.py — 7 قواعد حتمية قابلة للتفسير، كل قاعدة تُطلق اسمها + سبب نصيًا بالقيم الفعلية:
القاعدةالشرطالوزنالخطورة
flood_rateRate > 10,000 و syn_flag > 0.51.0high
volume_spikeTot_sum > 5,0000.9high
syn_no_ackRate > 500 و SYN بدون ACK0.8medium
reset_stormrst_count > 50.6medium
oversized_headerHeader_Length > 5000.6medium
icmp_anomalyICMP مع Rate > 1,0000.6medium
arp_activityوجود حركة ARP0.3low
  • detection/ml_detector.py: Isolation Forest + Autoencoder (MLP) مدرَّبان على البيانات الطبيعية فقط، مع معايرة الدرجات بكمّيات التوزيع الطبيعي (q05 → 0، q99 → 1).
  • detection/fingerprint.py: بصمة سلوكية لكل جهاز (انحراف z عن خط أساسه + وسم الأجهزة الجديدة).
  • detection/engine.py: دمج مرجّح مع اتخاذ قرار إنذار:
fused_score = 0.5·ML + 0.35·Rules + 0.15·Fingerprint
is_alert = (fused_score >= 0.5)

2.4 طبقة التفسير (Explainability)

  • detection/explain.py: SHAP TreeExplainer (دقيق على Isolation Forest — المرجع الأساسي) + LIME (نموذج بديل محلي — فحص مرافق فقط).
  • annotate_alerts() تدمج إسنادات SHAP مع أسباب القواعد والبصمة في سجل الإنذار الواحد.
ℹ️ تحفّظ موثّق: دالة قرار IF متدرجة قطعيًا (piecewise-constant)، لذا إسنادات LIME المحلية ضجيجية — SHAP هو المرجع.

2.5 الخادم الخلفي (Backend)

  • backend/db.py: SQLite بوضع WAL، 5 جداول — alerts (مع لقطة الميزات الخام كاملة لقابلية إعادة الإنتاج)، devices، incidents، incident_events، audit_log. أعمدة JSON تُخزَّن TEXT وتفك عند القراءة.
  • backend/app.py: Flask REST API كامل + تقديم لوحة SOC من frontend/ على / و/health للفحص.
  • backend/ingest.py: جسر المحرك → قاعدة البيانات (الصفوف الموسومة is_alert فقط تصبح سجلات إنذار؛ كل الصفوف تحدّث last_seen للأجهزة).

2.6 لوحة SOC (Frontend)

  • HTML/CSS/JS خام بدون أي framework — ثيم SOC داكن، استطلاع كل 5 ثوانٍ.
  • صف إحصائيات حي + جدول إنذارات قابل للتصفية + حالة الأجهزة مع زر عزل + تفاصيل كل إنذار (أشرطة الدرجات: الثقة المدمجة / ML / القواعد / البصمة + إسناد SHAP + أسباب القواعد) + خطوط زمن التحقيقات.
  • scripts/seed_demo.py: يسرّع قاعدة بيانات عرض تجريبية كاملة (29 إنذار + incident) ويشغّل الخادم — تم التحقق البصري داخل المتصفح.

2.7 طبقة التنبيه (Alerting)

  • backend/alerting.py: TelegramNotifier (Bot API بحد أدنى 1.1 ثانية/رسالة — الفائض يُسقَط بسلامة) + WebhookNotifier (POST للـ JSON على قائمة WEBHOOK_URLS) + AlertDispatcher (fanout لكل المُعِدين).
  • لا ترتفع أي استثناء إلى خط الكشف — الفشل الشبكي/الغياب = no-op مع تسجيل.
  • اكتشفت الاختبارات عيبًا حقيقيًا وأصلحته: مفتاح النتائج كان اسم الفصل → تكرار نفس الفئة يفقد نتيجة؛ أُعيدت الصياغة لقائمة مرتبة.

2.8 طبقة الوكلاء (LLM Agents) — أكبر بنود المرحلة

أ. السقالة المشتركة agents/scaffold.py

  • ScopePolicy: قفل النطاق — الأهداف المحمية (gateway, broker, mosquitto, soc, dashboard) مطابقة بنص فرعي غير حساس لحالة الأحرف؛ لا يمكن للمستهدف المحمي أن يُلمس أبدًا.
  • RateLimiter: فاصل أدنى بين النداءات + ميزانية لكل نافذة زمنية، مع ساعة قابلة للحقن لاختبارات حتمية.
  • LLMAgent: حلقة tool-calling على أي عميل بشكل OpenAI SDK (chat.completions.create) — الحاجز يرد الرفض إلى الـ LLM كرسالة أداة خطأ (ScopeViolation/RateLimitExceeded) فيبدّل هدفه بدل الانهيار؛ حد أقصى max_rounds يرفع AgentLoopError.

ب. وكيل الهجوم agents/attack.py (DeepSeek)

  • النموذج: deepseek-chat عبر https://api.deepseek.com (متوافق مع OpenAI SDK، الاستيراد كسول).
  • الأدوات: list_attack_types (كتالوج السيناريوهات) · deploy_attack (يولّد traffic محاكى في مخطط CICIoT2023 → يمسّه المحرك → يستوعب + audit؛ محدود 10 نداءات/دقيقة) · get_network_state.
  • الحماية: الهدف يُفحص على مستوى الحلقة وعلى مستوى المعالج (دفاع متعمق).

ج. وكيل الدفاع agents/defense.py (Groq)

  • النموذج: llama-3.3-70b-versatile عبر https://api.groq.com/openai/v1.
  • 6 أدوات: get_alert_details · list_open_alerts · correlate_alerts (تجميع device×class لكشف الحملات) · create_incident · append_timeline_event · request_isolation.
  • الوكيل لا يلمس حالة الأجهزة مباشرة — كل عزل يمرّ إجباريًا عبر طبقة الاستجابة.

3. الاختبارات والتحقق

  • 124 اختبار ناجحة تغطي: المخطط والبيانات، كل قاعدة، IF/AE/البصمة، الدمج، SHAP/LIME، الـ API (بما فيه end-to-end محرك→SHAP→DB→API)، الـ alerting (شبكة mocked)، السقالة (حلقة أدوات كاملة بعملاء مزيفين)، الوكلاء، سياسة الاستجابة.
  • اختبار end-to-end بالوكيل الافتراضي يثبت المسار كاملًا: LLM مزيف → أدوات دفاع → عزل فعلي في DB + audit + timeline.
  • كل العملاء injectable — لا نداء API حقيقي واحد في أي اختبار.
  • الأمران المُتحقق منهما: .venv\Scripts\ruff.exe check . و .venv\Scripts\python.exe -m pytest tests -q.

7. المراجع التفصيلية

  1. CICIoT2023 Dataset: Neto, E. C. M. et al. — "CICIoT2023: A Real-Time Dataset and Benchmark for Large-Scale Attacks in IoT Environment", Sensors 2023, 23(13), 5941 — MDPI. صفحة المجموعة: https://www.unb.ca/cic/datasets/iotdataset-2023.html (رخصة CC BY 4.0). استخدمنا منه مخطط الـ 48 ميزة (Rate, Header_Length, syn_flag_number, Tot_sum, ...) وتصنيف الصنفين DoS/Spoofing.
  2. Isolation Forest: Liu, F. T., Ting, K. M., Zhou, Z.-H. (2008). "Isolation Forest". IEEE ICDM 2008 — الأساس النظري لكاشف الشذوذ الرئيسي في المحرك.
  3. SHAP: Lundberg, S. M., Lee, S.-I. (2017). "A Unified Approach to Interpreting Model Predictions". NeurIPS 2017 — الإطار المرجعي للتفسير؛ تنفيذنا TreeExplainer (شجري دقيق) عبر مكتبة shap ≥0.45.
  4. LIME: Ribeiro, M. T., Singh, S., Guestrin, C. (2016). "'Why Should I Trust You?': Explaining the Predictions of Any Classifier". KDD 2016 — الفحص المرافق عبر مكتبة lime ≥0.2.
  5. scikit-learn: Pedregosa et al. (2011). "Scikit-learn: Machine Learning in Python". JMLR 12 — IsolationForest, MLPRegressor, preprocessing.
  6. MQTT v5: OASIS Standard (2019) https://docs.oasis-open.org/mqtt/mqtt/v5.0/ + Mosquitto broker https://mosquitto.org/ — بروتوكول تليمتري الأجهزة المستهدف في كاشفنا والبروكر المحمي.
  7. DeepSeek API: https://api-docs.deepseek.com/ — endpoint متوافق OpenAI؛ النموذج deepseek-chat لوكيل الهجوم.
  8. Groq API: https://console.groq.com/docs — endpoint متوافق OpenAI؛ النموذج llama-3.3-70b-versatile (Meta Llama 3.3) لوكيل الدفاع.
  9. OpenAI Python SDK: https://github.com/openai/openai-python — شكل العميل المرجعي للحلقة (chat.completions + function calling) وبُني عليه السقالة القابلة للحقن.
  10. Telegram Bot API: https://core.telegram.org/bots/api — sendMessage مع rate limit الرسمي ~1 رسالة/ثانية لكل محادثة (طبقنا 1.1s).
  11. Flask: Pallets Projects https://flask.palletsprojects.com/ — REST API وتقديم اللوحة.
  12. ESP-IDF / frame injection: Espressif esp_wifi_80211_tx() https://docs.espressif.com/projects/esp-idf/ — أداة حقن إطارات 802.11 المخططة للمرحلة 2 (Deauth/Rogue AP عبر ESP32، غير Arduino).
  13. NRF24L01: مواصفات Nordic Semiconductor nRF24L01+ — راديو 2.4GHz لاختبارات التشويش في المرحلة 3 داخل حجرة محصّلة.
  14. الامتثال RF (مصر): لوائح هيئة تنمية صناعة تكنولوجيا المعلومات (NTRA) للاختبارات الترددية — كل توليد هجوم RF مقيد بحجرة مشحّدة فيزيائيًا، ولا هجوم خارج الشبكة المخبرية.
  15. ruff / pytest: أدوات الجودة — ruff ≥0.6 (lint) وpytest ≥8.0 (124 اختبارًا).
